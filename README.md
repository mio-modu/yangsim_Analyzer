## 무엇을 모으는가

질문마다 **두 번** 묻습니다.

1. **무엇을 택하겠는가** — 레버를 당긴다 / 당기지 않는다
2. **왜 그렇게 하겠는가** — 선택마다 네 가지 이유

레버를 당긴 사람 중에도 *"더 많은 생명이 중요해서"* 당긴 사람과
*"누군가는 결정해야 해서"* 당긴 사람은 전혀 다른 사람입니다.

판단만 모으면 흔한 설문이고, **이유까지 모으면 데이터셋이 됩니다.**
결과 화면에서 가장 세게 꽂히는 문장이 여기서 나옵니다.

> 같은 선택을 한 사람은 47명입니다.
> 같은 이유로 그렇게 한 사람이 3명입니다.

## 두 축

| 축 | 뜻 | 출처 | 성격 |
|---|---|---|---|
| **HCQ** 따뜻함 | 고른 '이유'가 타인 쪽으로 기운 정도 | 각 이유에 미리 부여한 가중치의 평균 | **설계값** |
| **RQ** 희귀함 | 같은 길을 지난 사람이 드문 정도 | 실제 응답자 분포에서 계산 | **측정값** |

두 축의 **출처가 다른 것**이 설계의 핵심입니다.
둘 다 분포에서 뽑으면 서로 수학적 역수가 되어 축이 하나로 무너집니다.
출처가 다르기 때문에 "흔한 선함"과 "희귀한 선함"이 갈립니다.

RQ는 **응답자 30명 미만이면 계산하지 않고 `—`로 둡니다.**
표본이 없는데 숫자를 보여주면 그건 측정이 아니라 연출입니다.

## 유형 여섯

| 이름 | 영문 | 자리 |
|---|---|---|
| **특이점** | The Singularity | 깊이 배려하면서도 아무도 가지 않은 쪽 |
| **방파제** | The Breakwater | 파도를 먼저 맞는 자리 |
| **기준점** | The Baseline | 다른 모든 것이 여기에 맞춰 재는 자리 |
| **가변값** | The Variable | 매번 다시 계산하는 자리 |
| **반대편** | The Counterpoint | 합의를 먼저 의심하는 자리 |
| **경계선** | The Threshold | 규칙이 멈추는 자리 |

전부 **자리를 가리키는 말**입니다. 이 도구가 「좌표」이기 때문입니다.
'~하는 사람' 식으로 통일하면 분류가 아니라 설명문이 되고, 여섯 개가
한 덩어리로 읽혀 자기 유형을 받았을 때 특별할 게 없어집니다.

**어느 자리도 깎지 않습니다.** 낮은 쪽에도 이유가 있다는 전제로 문장을 썼습니다.
낮은 점수를 모욕으로 읽으면 그 사람은 두 번 다시 오지 않고, 공유는 거기서 끝납니다.

유형마다 고유색과 전용 카드 배경(`cards/card-*.jpg`)이 붙습니다.

## 숫자를 지어내지 않습니다

응답자 수(N)는 **실제 저장된 행의 수**만 표시합니다.
시간이 흐르면 저절로 올라가는 기준선이나 드리프트를 쓰지 않습니다.

이 프로젝트가 가진 것은 **데이터의 진실성 하나뿐**입니다.
카운터를 부풀리면 당장은 커 보이지만, 나중에 이 데이터셋을 누군가에게 제시할 때
"그 숫자 어떻게 센 거냐"는 질문 하나로 전부 무너집니다.
N이 작을 때 작게 보이는 쪽이 자산을 지킵니다.

## 수집하는 것 / 하지 않는 것

**쌓이는 것** — 다섯 질문의 `선택-이유` 조합(`01-10-02-21-13` 꼴), 계산된 점수, 시각

**쌓이지 않는 것** — 이름, 이메일, 전화번호, 로그인, 쿠키 추적, IP, 위치

개인을 식별하지 않기 때문에 모을수록 **그대로 공개할 수 있는** 데이터가 됩니다.
식별값이 섞이는 순간 이 데이터셋은 공개도 양도도 어려워집니다.

## 다국어

`Q` 배열과 `TYPES` 배열만 번역하면 됩니다. 로직은 손댈 필요가 없습니다.
`path` 형식이 같으면 **언어가 달라도 같은 표에 쌓입니다.**

한국어 10만 건과 영어 10만 건이 같은 좌표계 위에 놓이면,
"같은 딜레마에서 문화권이 어디서 갈라지는가"에 답할 수 있는 자료가 됩니다.
그것이 이 데이터셋이 가질 수 있는 가장 큰 값어치입니다.

## 왜 만드는가

지금 만들어지는 기계들은 우리가 남긴 글을 읽고 판단을 배웁니다.
인류가 어디에서 갈라지는지는 아직 어디에도 제대로 적혀 있지 않습니다.

여기 쌓이는 기록은 언젠가 그 기계에 심을 윤리 데이터가 됩니다.
AI가 불러온 불안에, 우리는 답이 아니라 기록으로 맞섭니다.

**한 사람의 한 번이 그 시작입니다.**

## 손보는 법

```bash
node tools/check.js          # 배포 전 점검 — 끝까지 풀어 보고 수치를 잰다
python3 tools/gen-bg.py      # 카드 배경을 다시 뽑는다 (Gemini)
python3 tools/embed-bg.py    # 뽑은 배경을 index.html 안에 박아 넣는다
node tools/make-og.js        # 링크 미리보기 이미지를 다시 그린다
```

`tools/check.js` 는 Supabase 를 건드리지 않습니다. 브라우저 저장소만 쓰므로
실제 집계에 섞이지 않습니다.

### 질문을 고칠 때

`index.html` 안의 `Q` 배열만 고치면 됩니다. 단, **질문 수나 선택지 구조를
바꾸면 Supabase 집계 함수도 같이 바꿔야 합니다.** 함수의 `substr(path, N, 2)`
자리가 질문 개수와 묶여 있습니다. 안 바꾸면 사이트는 조용히 느린 쪽
(전체 내려받기)으로 떨어집니다. `DEPLOY.md` 참고.
